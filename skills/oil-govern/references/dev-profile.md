# 项目开发约定（oil-dev）格式与生成指南

本文配合 `oil-govern` 使用。开发约定是写在目标仓库 `AGENTS.md` 里的一个小节，把整套流程每一步都要用到的事实固定下来：快测怎么跑、合并前跑什么、哪些目录高风险、哪些目录不能手改。写好之后，`oil-explore`、`oil-plan`、`oil-code-review` 会直接读取，不用每次重新猜。

## 1. 格式

在 `AGENTS.md`（没有时用 `CLAUDE.md`）里加一个标题含 `oil-dev` 的小节，每行一个条目，命令和路径用反引号包起来：

```markdown
## 开发约定（oil-dev）

- 快测：`pytest tests/{target} -q`
- 重测：`pytest -m slow`
- 门禁：`make ci`
- 高风险：`src/storage/**`、`src/auth/**`、`migrations/`
- 禁改：`vendor/`、`src/generated/**`
```

| 条目 | 英文写法 | 含义 | 必填 |
| --- | --- | --- | --- |
| 快测 | `quick-test` | 改完一个模块后跑的秒级测试命令；`{target}` 代表模块、类名或文件过滤条件 | 是 |
| 重测 | `full-test` | 端到端、全量集成、重计算回归等慢测试 | 否 |
| 门禁 | `merge-gate` | 合并前跑一次的完整检查（全量测试、类型检查、构建或打包冒烟） | 是 |
| 高风险 | `high-risk` | 改到这里就走独立深审的目录；支持 `*`、`**`，以 `/` 结尾表示整个目录 | 是 |
| 禁改 | `do-not-edit` | 生成代码、vendored 第三方代码等不允许手改的目录 | 否 |

书写规则：

- 小节从标题开始，到下一个同级或更高级标题为止；代码块里的内容不计入。
- 条目名可以加粗，冒号中英文都行；多个值分别用反引号包住。
- 英文仓库可写 `## Dev profile (oil-dev)` 并使用英文条目名。
- 控制在 10 行以内：它是常驻规范的一部分，每次对话都会加载。

## 2. 谁在用、怎么用

| Skill | 用法 |
| --- | --- |
| `oil-explore` | 结构快照直接展示这一节，确认测试命令时以它为准 |
| `oil-plan` | 快测与门禁写进验证标准和派发契约；禁改目录写进禁改范围；改动落在高风险目录时按中途升级规则处理 |
| `oil-code-review` | 采集脚本标出改到高风险目录和禁改目录的文件；高风险目录一律走独立深审 |
| `oil-govern` | 体检时检查是否缺这一节、缺哪些必填项，以及高风险目录规则是否已经匹配不到任何文件 |

## 3. 怎么生成

1. 运行 `AUDIT_REPO --scope all`，从 `defined_scripts`（package.json、Makefile、justfile、`scripts/` 与 `ci_run_steps`）里找测试与检查命令。
2. **快测**：找能按模块或文件过滤的命令，实际跑一次，确认几秒到几十秒内完成，再把过滤部分换成 `{target}`。找不到可过滤的入口时，在体检报告里提出来，建议先补一个（见测试治理）。
3. **门禁**：优先使用 CI 里实际执行的那组命令；没有 CI 时，用仓库已有的全量测试加构建命令。
4. **高风险**：从下面几类里挑出仓库中真实存在的目录，再请用户确认增删：
   - 数据存储格式、数据库结构与迁移、缓存与同步
   - 鉴权、权限、支付、密钥与个人数据处理
   - 文件删除、批量覆盖等不可逆操作
   - 并发、异步与后台任务调度
   - 对外 API、CLI 参数、配置文件格式、SDK 公共接口
   - 打包、发布、安装与升级流程
   - 快照中改动频繁的超大文件
5. **禁改**：生成代码目录与 vendored 第三方代码。被 Git 忽略的目录本来就不会出现在改动里，不用写。
6. 起草后给用户看，确认后再写入 `AGENTS.md`。之后目录改名、新增高风险模块或测试入口变化时，同步更新这一节；体检报告提示“匹配不到任何文件的高风险目录”时，优先处理。
