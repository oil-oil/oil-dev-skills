# oil-govern

`SKILL_DIR` 指当前 Skill 的绝对目录；`<python>` 指 Python 3.10+（macOS/Linux 通常为 `python3`，Windows 通常为 `py -3`）；`AUDIT_REPO` 是 `<python> "$SKILL_DIR"/scripts/audit_repo.py` 的简写。

## 核心规则

- **脚本只采客观事实，语义判断交给模型**：先运行轻量脚本 `AUDIT_REPO` 秒级获取文档死链与新鲜度、文件体积、Git 演进温差、超大活跃文件、CI 实际执行的命令与 Worktree 合入状态，不在通用脚本里堆砌生硬的硬编码正则；拿到客观数据后再定向阅读具体文件做准确判断。
- **规范单源维护、同时控行控体积**：以 `AGENTS.md` 作为统一规范源，其他宿主规则入口文件用单行 `@AGENTS.md` 引用避免分叉或漏加载；同时控制常驻文件的行数与总字节数（防超长段落隐性膨胀），区分“常驻活文档”与“一次性历史快照”。`AGENTS.md` 里维护一个 `oil-dev` [开发约定](references/dev-profile.md)小节（快测、门禁、高风险目录、禁改目录），供其他 Skill 直接读取。
- **测试分层控频、重质且无副作用**：把秒级局部快测与高耗时重测（E2E、媒体编解码、全量集成、打包冒烟）拆开，在 `AGENTS.md` 明确约定“日常小改按需跑局部快测，大批量调整完成或合并主干前再统一跑一次重测”，并排查无人执行的孤儿测试与混入快测层的慢用例。
- **专属规矩落地在目标项目内部**：凡是能静态判定的项目专属约束（架构禁引、设计令牌、多语言配对、打包产物检查），写成**目标仓库自己的**轻量静态测试或检查脚本接入构建门禁，不每次靠 AI 读文字自觉遵守。

## 先选择模式

| 模式 | 适用情况 | 路径 | 默认停止点 |
| --- | --- | --- | --- |
| 全仓体检 | 阶段性维护，快速盘点文档、测试与 Worktree 现状 | `AUDIT_REPO --scope all` → 定向抽查热点文件 → 输出分级整改清单 | 呈现客观问题清单请用户勾选 |
| 文档与规范治理 | 同步入口规则、清理过期描述/死链、归档过程快照、建立或校准开发约定 | `AUDIT_REPO --scope docs` → 对照近期活跃代码核查核心文档 → 更新瘦身 | 常驻文档准确清爽、零死链且开发约定可用 |
| 测试分层与瘦身 | AI 跑测试太频繁太慢、存在孤儿/无效测试或漏测盲区 | `AUDIT_REPO --scope tests` → 拆分快慢入口 + 写控频规则 + 清理慢/假测试 | 跑通快测入口并确认重测分层 |
| Worktree / 脚本化 / 止损 | 清理并行工作树、把文字规矩写成项目内静态检查、或止损顽固难题 | 盘点 Worktree / 编写项目内检查测试 / 按三步止损法双模型会诊 | 完成清理、接入检查或给出止损建议 |

## 工作流

### 1. 采集客观治理快照

动手修改前先运行只读采集脚本（支持 `--scope all|docs|tests|worktrees` 与 `--json`）：

```text
AUDIT_REPO --workspace "<项目路径>" --scope all
```

### 2. 文档与规范治理

结合快照中的 `docs` 与 `code_and_tests.top_dir_recent_commits`，对照 [治理实操指南](references/governance-guide.md#1-文档与规范治理单源减负与事实保鲜) 定向检查：

1. **入口规则单源同步与减负**：检查团队使用的各宿主规则入口文件是否齐全且统一通过 `@AGENTS.md` 引用；若 `AGENTS.md` 或 `DESIGN.md` 体积过大（如超过 10 KB），把局部子系统的实现细则下沉到 `docs/` 专题文档。
2. **核查核心文档的事实性过期**：快照会给出每篇文档距最近修改的提交数与天数（`docs/` 按最久未修改排序）。若源码目录持续活跃，而 `README.md` 或架构总览文档已经几十上百次提交没动过，重点核对其中的“不做边界、第三方依赖口径、模块目录树与核心管线描述”是否已与现状矛盾。
3. **清理死链与过程快照**：修复常驻文档中的失效相对链接；若 `docs/` 堆积了大量多轮审查过程快照（如阶段性改动清单），提议归入 `docs/archive/` 或直接清理。
4. **建立或校准开发约定**：快照提示“未找到开发约定”、缺少必填项，或有高风险目录已匹配不到任何文件时，按 [开发约定格式与生成指南](references/dev-profile.md) 起草或修订这一小节（快测命令要实际跑一次确认够快），给用户确认后再写入 `AGENTS.md`。

### 3. 测试分层、控频与质量治理

结合快照中的 `test_directories`、`defined_scripts` 与项目实际测试脚本，对照 [测试分层与瘦身指南](references/governance-guide.md#2-测试治理快慢分层控频瘦身与隔离安全) 处理：

1. **快慢分层与触发频率约束**：确认仓库是否具备按模块/类名过滤的**秒级局部快测入口**，以及通过独立命令或环境变量门禁隔离的**高耗时重测入口**；在 `AGENTS.md` 明确写清“编码途中只跑编译、类型检查这类秒级检查，不频繁跑测试；每轮改完跑关联局部快测（失败修完再跑同一条）；全量回归与打包检查在整批收尾或合并前统一跑一次”。
2. **排查孤儿测试与慢单测混入**：以快照里的 `ci_run_steps`（CI 实际执行的命令）和已定义脚本为准，逐个核对测试目录是否真被某条命令执行到，没被任何入口覆盖的就是孤儿测试候选；快照提示“未发现 CI 配置”时，如实说明无法客观确认，只能对照本地测试入口判断。若有耗时几十秒的重计算用例混在普通单测层，提议抽离或优化。
3. **清理无效测试并守住隔离底线**：清理零业务断言、重度 mock 自证或硬写长 `sleep` 的低价值测试；确认客户端/桌面测试全程无头运行、不弹窗抢焦点、不污染用户真实配置域。

### 4. Worktree 卫生、项目内脚本化与疑难止损

- **并行 Worktree 与分支清理**：若快照显示子 Worktree 直接嵌套在主仓库目录内，建议移至同级父目录或加入忽略规则。按快照里的合入状态区别对待：
  - 标为“可清理候选”的（普通合并、squash 或 rebase 合入，且没有未提交改动）：提示直接切新分支复用其热编译缓存，或移除回收空间。
  - 标为“没有独立提交”的：可能是刚建还没开工，也可能已快进合并，脚本无法区分，先问用户。
  - 有未提交改动的：一律不清理，先告诉用户有哪些改动。
  - “远端分支已删除”只是辅助信号，不能单独作为清理依据。
  - 执行 `git worktree remove` 或删除分支前，列出清单并征得用户确认。
- **项目硬规则转静态测试**：阅读 `AGENTS.md` / `DESIGN.md` 中的明确禁令（如分层禁引、禁用控件样式、单文件行数阈值、打包资源规范），在**目标仓库的测试套或 `scripts/`** 中编写简洁易读的静态检查。
- **顽固边缘问题三步止损**：遇到连修两轮仍卡死、越改越乱，或 `oil-code-review` 中同一条 `Must Fix` 两轮仍未通过的难题，按 [三步止损法](references/governance-guide.md#4-疑难问题与复杂边缘需求的三步止损法) 执行用户对齐、双独立强模型只读会诊与果断做减法。

## 输出与后续衔接

体检阶段只输出有确切依据的事实清单与优先级建议；用户确认要改的项后再落盘修改并验证。

| 下游意图 | 衔接动作 |
| --- | --- |
| 将某条硬规矩落地为目标仓库内的静态测试后清理旧审查项 | 配合 `oil-code-review` 删掉重复的人工审查规则 |
| 对修了两轮仍卡住的疑难故障做双模型盲诊 | 用 `oil-delegate` 的 `--role diagnose`，分别以 `--role-slot 1` 和 `--role-slot 2` 派发两路独立分析（自动只读；某一路返回 `USE_HOST` 时由当前 Agent 的全新子 Agent 承担；返回 `NEEDS_ROLE_CHOICE` 时问用户一次要哪两个），回来后确认 `git status` 没有变化 |
