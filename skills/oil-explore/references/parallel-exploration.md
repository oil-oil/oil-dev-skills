# 并行只读探索切片指南

当处于陌生大仓库或跨多子系统改造（`thorough` 档）、且当前环境支持启动只读子 Agent 时，按本文拆分任务并回收精简摘要。

## 1. 切片原则：按独立子系统拆，不按同文件概念硬拆

- **按目录/模块边界切分**：例如涉及“导出管线 + 时间线交互 + 公共组件库”时，让三个只读子 Agent 各自负责一个独立目录树，避免多个子 Agent 打开同一批视图与状态文件重复消耗上下文。
- **单模块耦合紧密时不硬拆**：如果入口界面、状态绑定和所用组件都在同一个模块目录内，保留单路探索即可，不要为了凑并行数量拆成三路。
- **显式选用轻量快速模型档位**：探索动作主要是搜符号和核对调用链，优先为子 Agent 指定轻量快速档位，并锁死只读边界（不改文件、不跑构建或有界面副作用的命令）。

## 2. 给探索子 Agent 的提示词骨架

```text
只读探索任务（严禁修改任何文件，严禁运行编译打包或会弹窗的命令）：
- 探索目标：<一句话说明本切片要查清的具体问题>
- 负责目录范围：<指定独立子系统目录，不要越界扫描其他模块>

请用检索工具定位并按局部行号精读关键定义，在 20 行以内返回：
1. 核心调用与数据流：`文件路径:起始行-结束行` + 符号名 + 一句话职责
2. 仓库内可直接复用的现成组件 / 函数 / 共享类型
3. 该模块对应的现有测试文件与局部快测命令
4. 仍待确认的耦合风险或产品分歧
```

## 3. 汇总交付简报结构

```markdown
### 探索结论简报
- **核心链路**：
  - `path/to/entry:42-68`（`SymbolA`）：负责接收操作并校验状态，调用下层服务。
  - `path/to/core:105-148`（`SymbolB`）：处理核心计算并更新持久化数据。
- **可直接复用的已有基建**：
  - 公共组件 / 令牌：`<目录或文件路径>`
  - 共享逻辑模块：`<目录或文件路径>`
- **关联测试与局部快测命令**：
  - 测试文件：`<测试文件路径>`
  - 局部快测：`<按模块或类名过滤的秒级测试命令>`
- **待确认边界**：
  - <代码无法单独决定、需在方案阶段请用户确认的取舍>
```
